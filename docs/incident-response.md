# Incident Response Playbook

This playbook provides a practical response workflow for identity and Azure control-plane alerts generated by this lab.

## 1. Triage

For every alert, record:

- alert name and timestamp
- affected user, service principal, subscription or resource
- source IP and location when available
- initiating identity
- correlation or operation ID
- whether the activity succeeded
- whether the activity was expected

## 2. Identity compromise

Use this flow for repeated failed sign-ins, risky sign-ins and unexpected privileged-role changes.

1. Validate the identity and recent authentication history.
2. Review successful sign-ins around the alert window.
3. Compare source IPs, user agents, locations and Conditional Access results.
4. Review recent password, MFA and directory-role changes.
5. Revoke active sessions if compromise is suspected.
6. Reset credentials and require MFA re-registration when appropriate.
7. Remove unauthorized role assignments.
8. Hunt for the same infrastructure or IP across other identities.
9. Document scope, actions and recovery evidence.

## 3. Azure control-plane incident

Use this flow for suspicious RBAC changes, destructive operations or unexpected resource modifications.

1. Identify the caller and authentication method.
2. Review Azure Activity around the same correlation ID and caller.
3. Confirm whether the change matches an approved administrative task.
4. Review role assignments at management-group, subscription, resource-group and resource scope.
5. Remove unauthorized permissions.
6. Disable or rotate compromised service-principal credentials when applicable.
7. Restore deleted or modified resources using the relevant recovery mechanism.
8. Hunt for additional writes, deletes and policy changes by the same caller.

## 4. Severity guidance

| Severity | Example |
|---|---|
| Informational | Expected administrative change |
| Low | Repeated failures with no successful authentication |
| Medium | Unusual successful sign-in requiring investigation |
| High | Unexpected privileged role assignment |
| Critical | Confirmed compromise combined with destructive Azure activity |

## 5. Evidence preservation

Preserve relevant Sentinel incidents, KQL query results, Azure Activity records, Entra sign-in/audit records and timestamps before remediation where possible.

## 6. Closure criteria

Close an incident only when the initiating identity is understood, unauthorized access is contained, persistence has been removed, affected resources are recovered and follow-up controls have been identified.
